**Goal:** Build a hosted Guardian customer transfer flow and operator investigation console, with evidence-linked AI and enforceable synthetic monetary decisions.

**Architecture:** Preserve Nemo's Next.js frontend. Add a modular FastAPI backend, PostgreSQL and private image storage. Server-authenticated customer/operator sessions own all financial and policy decisions; model output is reviewed evidence.

**Tech Stack:** Existing Next.js/React/TypeScript/Tailwind stack, Python 3.12+, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, PostgreSQL 16+, one vision-capable model provider, GCP hosting.

**Spec:** `docs/guardian/product-requirements.md`, `architecture.md`, `data-model.md`, `database-specification.md`, `schema.sql`, `openapi.yaml`, `scenarios.md`, `evaluation.md`, `cloud-deployment.md`.

## Global Constraints

- `Frontend/` and `Backend/` keep their existing casing.
- Customer and operator are the two application roles. The demo controller only manages synthetic scenarios.
- A draft does not reserve funds. The first confirmation attempt re-evaluates risk and either executes or enters a hold atomically.
- AI has no general SQL, shell, money-movement or policy-change tool.
- All payment balances, orders, partners and financial outcomes in the contest build are synthetic.
- A held transfer reserves funds for 15 minutes by default. Cancellation, rejection or expiry releases the reservation.
- Operator clearance requires a fresh customer confirmation before execution.
- Follow `Frontend/AGENTS.md` and read relevant installed Next docs before editing frontend code.
- Use one agreed OpenAPI contract. Update SQL, API, fixtures and consumers together when a behavior changes.
- Existing repository policy allows merges into master from dev. Integration work goes through the team's dev workflow.

## Review Focus

1. A customer acknowledges an old warning after OPS adds a HOLD. Task 3 must prove current enforcement wins.
2. Confirm/cancel/expiry races can lose or duplicate reservations. Tasks 2 and 5 must prove account/transfer/ledger consistency with PostgreSQL.
3. A screenshot contains another sandbox ID or a prompt instruction. Tasks 4 and 6 must prove ownership checks and untrusted-content handling.
4. A reference code appears in a forwarded screenshot. Task 6 must retain uncertainty and require reviewed report/batch evidence for publication.
5. Model/cleanup/container failures can leave incomplete state. Tasks 4, 5 and 8 must prove timeout recovery and deadline enforcement.
